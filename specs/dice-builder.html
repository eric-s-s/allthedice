Dice Builder Spec

A Build button on each dice collection row opens a modal where the user puts together a dice collection by clicking instead of typing its build string.

One rule for the text box: the builder writes only build strings that it can read back. Opening the builder on a row parses the row's text. If the parse works, the modal starts with those dice. If it fails, the modal starts empty and says that Done will replace the text.

1. Goals

  1. Each dice collection row has a Build button that opens a modal dice builder for that row.
  2. Common dice take one click each. Preset buttons D4 D6 D8 D10 D12 D20 D100 add a die. Clicking the same preset again adds 1 to its count, so clicking D6 three times gives 3*Die(6).
  3. A custom die can be a Die, ModDie, WeightedDie or ModWeightedDie. The user picks the kind, sets the sides, a modifier and the weights where the kind uses them, and adds it.
  4. Each part of the collection has a count (the *) and at most one wrapper: Best of pool, Worst of pool, Exploding or Strong. Parts are joined with &.
  5. A single collection modifier (Modifier(n)) is set with − / + buttons.
  6. A live preview shows the build string, so the user also learns how to type it.
  7. Done writes the build string into the row and calculates it. Cancel, the close button and Escape leave the row unchanged.
  8. Reopening the builder on a row it filled shows the same dice again, ready to edit.

Out of scope: the Lambda API (the server still validates every build string, and its errors show on the row as they do today), the Examples menu, stats, plot, roller, stacked wrappers, ExplodingOn, setting the number of explosions, and the upper/lower mid pools.

2. Build string format

The builder writes exactly this grammar. The parser accepts the same grammar, with any whitespace between tokens and an optional 1*.

collection := part ('&' part)* ['&' 'Modifier(' int ')']   (or just the Modifier)
part       := [count '*'] wrapped
wrapped    := die
            | 'BestOfDicePool(DicePool(' die ', ' poolSize '), ' keep ')'
            | 'WorstOfDicePool(DicePool(' die ', ' poolSize '), ' keep ')'
            | 'Exploding(' die ')'
            | 'StrongDie(' die ', ' multiplier ')'
die        := 'Die(' sides ')'
            | 'ModDie(' sides ', ' int ')'
            | 'WeightedDie(' weights ')'
            | 'ModWeightedDie(' weights ', ' int ')'
weights    := '{' face ': ' weight (', ' face ': ' weight)* '}'
  • A count of 1 is left out: Die(6), not 1*Die(6).
  • A collection modifier of 0 is left out. When it isn't 0, Modifier(n) comes last.
  • Weights are written in face order, and faces with weight 0 are left out: WeightedDie({1: 1, 3: 2}).
  • Spacing matches the Examples menu: ModDie(6, 2), {1: 1, 2: 2}.

Example: 2*Die(6)&BestOfDicePool(DicePool(ModDie(8, 1), 4), 3)&Modifier(-2)

Limits

valueallowed
countwhole number ≥ 1
sides (Die, ModDie)whole number ≥ 1
sides (WeightedDie, ModWeightedDie)whole number from 1 to 100. It's the number of weight boxes
weightwhole number ≥ 0, with at least one weight above 0
die modifier, collection modifierany whole number
pool sizewhole number ≥ 1
keepwhole number from 1 to the pool size
Strong multiplierwhole number ≥ 1

The builder checks these limits only. Anything else the server rejects (a pool too big to calculate, for example) shows up as the row's error after Done.

3. Data models (new js/dice-builder.js)

Every box keeps its raw text, the same way StatsRequest.lowInput does, so half-typed text like - survives a render. Text is turned into numbers only when the build string is made.

BuilderDie

A die that has been added. It's fixed after it is added; to change one, remove it and add a new one.

/**
 * @typedef {{kind: 'Die', sides: number}
 *     | {kind: 'ModDie', sides: number, modifier: number}
 *     | {kind: 'WeightedDie', weights: number[]}
 *     | {kind: 'ModWeightedDie', weights: number[], modifier: number}} BuilderDie
 * weights[i] is the weight of face i + 1
 */

BuilderPart

fieldtypenotes
idstringcrypto.randomUUID(), so syncViews can key the part rows
dieBuilderDie

wrapper'none' | 'best' | 'worst' | 'exploding' | 'strong' starts as 'none'
poolSizeInput, keepInputstring start as '2' and '1', the most common pool (advantage/disadvantage). Used by best and worst
multiplierInputstringstarts as '2'. Used by strong

The wrapper boxes keep their text when the wrapper changes, so switching from Best to Worst keeps the pool size and keep values.

CustomDieDraft

The custom die form, before Add.

fieldtypenotes
kind'Die' | 'ModDie' | 'WeightedDie' | 'ModWeightedDie' starts as 'Die'
sidesInputstringstarts as '6'
modifierInputstringstarts as '0'
weightInputsstring[]one per side, starting as '1'

Methods:

  • setSides(text) sets sidesInput. When the text is a whole number from 1 to 100, it resizes weightInputs to that length: it keeps the weights that are still in range, and new sides start at '1'. Other text leaves weightInputs alone.
  • toDie() returns a BuilderDie for the current kind, or null when a box the kind uses breaks a limit.

DiceBuilder

fieldtypenotes
partsBuilderPart[]in the order they were added
modifierInputstringstarts as '0'
draftCustomDieDrafta new draft per builder

Methods:

  • addPreset(sides): if a part is Die(sides) with no wrapper, its count goes up by 1. Otherwise it adds a new part with count 1. A count box holding invalid text counts as 0, so it becomes '1'.
  • addCustomDie() adds a part from draft.toDie(). It does nothing when that is null. The draft keeps its values, so the same die can be added again.
  • removePart(id).
  • stepCount(id, delta): a count below 1 stays 1. Parts are removed only with their × button. Invalid text steps as 0, then clamps.
  • stepModifier(delta): any whole number. Invalid text steps as 0.
  • toBuildString() returns string | null: the build string, '' when there are no parts and the modifier is 0, or null when any box breaks a limit.

Functions

functionreturnsnotes
parseWholeNumber(text)number | null Trims the text. /^-?[0-9]+$/ gives the number, and anything else gives null.
dieToBuildString(die)stringfor a BuilderDie. Also used as the die's label in the part row
partToBuildString(part)string | null null when the count or a box the wrapper uses breaks a limit
parseBuildString(text)DiceBuilder | null A hand-written tokenizer and recursive-descent parser for the grammar in section 2. Blank text gives an empty builder. Text outside the grammar (stacked wrappers, two Modifiers, a count on Modifier, a face below 1, or anything unknown) gives null, and so does a value outside the limits. Weights become the die's weights from face 1 to the highest face, and missing faces become 0. The draft starts fresh.

AppState (models.js)

/**
 * @typedef {object} DiceBuilderSession
 * @property {DiceTableRequest} diceTableRequest the row that Done writes to
 * @property {DiceBuilder} builder
 * @property {string} replacedText the row's text when it could not be parsed; '' otherwise
 */

AppState gets diceBuilder: DiceBuilderSession | null, which starts as null. While it isn't null, the modal is open.

4. Views

Markup (index.html)

  • diceTableRequestTemplate gets <button type="button" class="secondary build">Build</button> between the text box and Calculate.
  • One <dialog id="diceBuilder" aria-labelledby="diceBuilderTitle"> after </main>. It holds, in order:
    1. A header with <h2 id="diceBuilderTitle">Build a dice collection</h2> and an .iconButton close button (×).
    2. A replace note, <p class="builderReplaceNote" hidden>: "Done will replace …", filled with replacedText.
    3. Add a die: the seven preset buttons, each with data-sides.
    4. Custom die: a kind <select>, a Sides box, a Modifier box (shown for ModDie and ModWeightedDie), a weights area (shown for the weighted kinds) with one box per side labelled by its face, and then an Add custom die button. The button is disabled while draft.toDie() is null.
    5. Your dice: <div class="builderParts">, plus an empty note when there are no parts.
    6. Modifier: − / box / + for the collection modifier.
    7. Preview: <output class="builderPreview"> showing the build string, or "Fix the highlighted boxes" when toBuildString() is null.
    8. Cancel (.secondary) and Done (.primary).
  • <template id="builderPartTemplate"> holds one part row: − / count box / +, "×", the die label in <code>, a .builderWrapperControls group, and a remove × button. The group holds a wrapper <select> (No wrapper, Best of pool, Worst of pool, Exploding, Strong), Pool and Keep boxes (shown for the pools), and a Multiplier box (shown for Strong).
  • Every number box is type="text", for the same reason as the stats boxes: a number box reports '' for half-typed text like -, so the model couldn't keep the raw text. Boxes that can't be negative get inputmode="numeric", which gives phones the number pad. The die modifier box doesn't, because the number pad has no minus sign. The collection modifier has − / + buttons instead.
  • Every box and select is labelled. The fixed ones in the dialog use a wrapping <label> or aria-labelledby. The ones made per part or per face get an aria-label naming the die or face (for example "Count of Die(6)", "Weight of face 3").

Styles (styles.css)

  • .diceTableRequest gets a fifth grid column. On phones the text box keeps its own line, and Build, Calculate and × share the second line.
  • #diceBuilder uses --surface, --radius and --menu-shadow. Its width is min(40rem, 100vw - 32px), and its body scrolls. ::backdrop dims the page.
  • The dialog is pinned max(16px, 6vh) from the top instead of centered, and its height is at most what's left minus 16px. A centered dialog moves every time it grows or shrinks (adding or removing a part, showing the weights), which slid the presets and Add under the pointer and added unwanted dice.
  • Presets wrap as a row of .secondary buttons. Each part row is a grid: count, die and remove on the first line, and the wrapper group on the second, where it wraps on phones. A long die label wraps inside its own column.
  • [aria-invalid="true"] boxes get a --danger outline.
  • Step buttons reuse .iconButton.stepButton, which is already 44px on phones.

DiceTableRequestView (request-views.js)

  • RequestActions gets a third action, build, so the dice table actions become DiceTableRequestActions. The stats actions don't change.
  • The Build button calls actions.build(). update(model) disables it while isPending, the same as Calculate.

DiceBuilderView (new js/dice-builder-view.js)

One instance, made in onPageLoad around the static dialog.

/**
 * @typedef {object} DiceBuilderActions
 * @property {() => void} change  a box, select or button changed the builder
 * @property {() => void} done
 * @property {() => void} cancel
 */
  • The constructor attaches the listeners for the fixed controls. Each one changes session.builder (looked up through a getter, because the session changes on every open) and then calls actions.change(). Preset and Add buttons, the custom die form and the collection modifier steppers (through onPressAndHold) work this way.
  • Part rows are kept in a Map and synced with syncViews by part id. Each row's listeners write to its BuilderPart or call stepCount / removePart, then call actions.change().
  • The weight boxes are synced by index. The view adds or removes boxes until the count matches weightInputs.length, so a focused box keeps its focus.
  • The dialog's cancel event (Escape) calls preventDefault() and then actions.cancel(). The close button and Cancel call actions.cancel(), and Done calls actions.done(). The dialog is only ever closed by update. Some browsers ignore preventDefault() on a repeated Escape and close the dialog anyway, so a close event while a session is still open also calls actions.cancel().
  • update(session):
    • With null: if the dialog is open, it calls close().
    • Otherwise: if the dialog is closed, it calls showModal(). The first preset (D4) has autofocus. Then it writes every box with setInputValue, shows and hides the kind and wrapper fields, sets aria-invalid on each box that breaks a limit, fills the preview and replace note, and disables Done when toBuildString() is null or ''.
  • When the dialog closes, the browser puts focus back on the Build button that opened it.

5. Connecting views to models (interface.js)

  • Open: build for a row runs parseBuildString(request.buildStringInput). If it gets a builder, the session uses it with replacedText: ''. If it gets null, the session uses new DiceBuilder() with replacedText set to the trimmed text. Then it calls render().
  • Change: calls diceBuilderView.update(state.diceBuilder) only, not render(). Typing in the builder doesn't touch the plot, stats or roller, and Plotly doesn't re-plot on every keystroke.
  • Done: sets request.buildStringInput to toBuildString(), sets state.diceBuilder to null, calls render() to close the dialog, and then calls getDiceTable(request). Rendering first matters because getDiceTable returns without rendering when the request is already pending. Done does nothing when the build string is null or '' (the button is disabled anyway).
  • Cancel: sets state.diceBuilder to null and calls render().
  • render() calls diceBuilderView.update(state.diceBuilder) after the request views.
  • The rest of the page is inert while the modal is open, so the row can't be removed or resubmitted under an open session.

Script order

js/dice-builder.js loads after models.js, and js/dice-builder-view.js loads after request-views.js. Both go in index.html (with ?v=) and in pageScripts in tests/page.js. jsconfig.json already includes js/*.js, so typecheck picks them up.

9. Decisions and open questions

Decided

  1. One Build button per row. It writes to its own row, so there's never a question of which row gets the dice. It doesn't sit next to "+ Add dice collection".
  2. Done fills and calculates, like the Examples buttons.
  3. One wrapper per part. Stacked wrappers (Exploding(StrongDie(…)), a pool of exploding dice) are still typed by hand. Stacking would need an ordered list in the UI and could produce very slow server requests.
  4. No extras for now: no ExplodingOn, no explosion count (the server's default applies), and no upper/lower mid pools.
  5. The row's text is parsed, not remembered. Reopening reads the box rather than a builder saved on DiceTableRequest. Edits typed by hand after a build are picked up, Examples text the grammar covers opens in the builder, and nothing extra is stored on the request.
  6. Unreadable text is replaced, not merged. The modal starts empty, and the note shows what Done will overwrite. Cancel keeps it.
  7. Added dice are fixed. A part's count and wrapper can be edited, but its die can't. To change the die, remove the part and add a new one. This keeps the part rows small.
  8. Preset clicks merge into a plain part of the same die, so repeated clicks build up a count. They never merge into a wrapped part.
  9. Builder edits update only the modal. The rest of the page doesn't render until Done or Cancel.
  10. Weighted dice have faces 1 to N, with N up to 100. A weight of 0 leaves a face out. Faces below 1 need ModWeightedDie's modifier, or typing.
  11. The Strong multiplier is at least 1.
  12. The Examples menu is the reference for the grammar. It is the full and correct set of dice and wrappers the server accepts, and section 2 is the part of it the builder writes.
